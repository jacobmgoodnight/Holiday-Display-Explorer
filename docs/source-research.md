## Routing comparison

- [openrouteservice API](https://openrouteservice.org/dev/) supports driving matrices. [Restrictions](https://openrouteservice.org/restrictions/) govern request sizes; [plans](https://openrouteservice.org/plans/) now redirect to HeiGIT account information. A legacy/staging plan page still lists a free standard tier and 500 daily matrix calls / 40 per minute, but these are **not treated as a verified current entitlement**. Confirm dashboard quotas, commercial conditions and caching permission before activation. Private API key stays in optional Worker secret storage. Global OSM-based routing includes Indiana, but no live credential-backed coverage test was performed.
- [Mapbox Matrix](https://docs.mapbox.com/api/navigation/matrix/) supports travel time and distance with an access token, per-element usage billing, up to 25 coordinates for driving and 10 for driving-traffic. Matrix responses can be asymmetric or contain null unreachable cells. Browser integrations are documented; use token restrictions and the provider's applicable storage rules. Not configured; avoid assuming a permanent free quota.
- The implementation selects an optional openrouteservice proxy for predictable small requests and key privacy. Matrix requests are user-triggered, capped at 22 points and cached briefly in session memory. No routing backend means clearly labeled geographic ordering, never estimated road time from a fabricated speed.

## Maps and handoff

- [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started): `api=1`, driving mode, encoded origin/destination and pipe-separated waypoints; no API key required for navigation links. Mobile browser allowance is up to three intermediate waypoints; other platforms allow up to nine. Maximum URL length is 2,048 characters. We always use three intermediates plus a destination, with the previous segment's destination as the next origin. Every selected stop and endpoint is preserved. Individual next-stop links provide an alternative if the receiving navigation app ignores intermediates.
- [Apple Map Links / unified Maps URLs](https://developer.apple.com/documentation/mapkit/unified-map-urls): the legacy reference redirects to the unified documentation. This build uses the established `https://maps.apple.com/?daddr=LAT,LNG&dirflg=d` compatibility link. Current documentation rendered as a JavaScript-only page in this research tool, so modern unified URL details could not be independently extracted. Actual iPhone handoff remains a device-test requirement; do not claim verified native navigation. Check the destination preview because navigation may snap a coordinate to a nearby road/place.
- [OpenStreetMap tile policy](https://operations.osmfoundation.org/policies/tiles/): attribution, normal browser caching, no bulk downloading/offline prefetch; public tiles are not an SLA-backed commercial map service. Leaflet loads only visible interactive tiles. The service worker ignores all external requests.
- [GitHub custom Pages workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) supports build artifact upload and deployment with Pages/id-token permissions. Hash links avoid missing-path reloads.
- [Cloudflare rate limit binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/) supports Worker-side bounded requests; its local counters should not be described as a durable global cost ceiling.

## Follow-up findings

FrightMaps' [privacy policy](https://frightmaps.com/privacy), sections 5–6, explicitly describes discovery tools such as `find_haunts` and `get_haunt_details`. Free home-display results expose city-level location only; postcode, coordinates and phone numbers are withheld. Therefore even authorized AI-discovery access would not, by itself, populate routable residential stops. A separate authorized precise-location feed, club export with appropriate rights, or homeowner-supplied location is needed. Do not try to reconstruct withheld locations.

Indy Christmas Lights has an interactive [map](https://indychristmaslights.com/map.php) and [submission workflow](https://indychristmaslights.com/submit.php), but these do not document a licensed third-party export. An owner-approved JSON/CSV feed or scheduled export could be integrated. For editorial guides, obtain permission for a factual listing feed; do not copy descriptions or photos.

Once a source authorizes an export, a scheduled GitHub Action can fetch it server-side, validate it through the existing schema, and produce the static dataset. This avoids browser CORS limitations and keeps credentials in Actions secrets, but it does not confer data rights or recover intentionally withheld fields.
